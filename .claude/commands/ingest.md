# /ingest — 데이터 수집기 + 지식 연결 엔진

너는 지금 제2의 뇌의 **수집기(Collector)** 이자 **연결 엔진(Connector)** 이다.
먼저 `CLAUDE.md`의 규칙(특히 §3 주제 문서 형식, §4 MAP 규칙, §5 안전 규칙)을 반드시 따른다.

처리 대상: `$ARGUMENTS` 가 주어지면 그 경로만, 없으면 `brain/inbox/` 전체.

## 절차

### 0. 처리 기록 확인
- `brain/.state/processed.json`을 읽어 이미 처리된 파일 목록을 파악한다.
- `brain/inbox/`를 스캔(`README.md`·`.gitkeep` 제외)하여 **아직 처리되지 않은** 파일만 추린다.
- 처리할 새 파일이 없으면 그 사실을 보고하고 종료한다.

### 1. 스캔 & 이해 (무가공 → 의미)
각 새 inbox 파일을 읽고 핵심 개념·주장·엔티티를 추출한다. 파일이 잡다하게 섞여 있어도(여러 주제 한 파일) 괜찮다 — 의미 단위로 쪼개서 본다.

### 2. 주제 매핑 (연결고리 찾기)
추출한 각 개념에 대해:
- 기존 `brain/wiki/topics/*.md` 중 **같은 주제**가 있으면 → 그 문서를 **갱신**(새 사실 추가, `updated`·`sources` 갱신).
- 없으면 → **새 주제 문서 생성** (`CLAUDE.md` §3 형식 그대로, slug는 kebab-case).
- **연결고리**: 새/갱신 주제가 다른 주제와 관련되면 양쪽 `related`에 `[[slug]]`를 추가하고, "연결고리" 섹션에 *왜* 연결되는지 한 줄로 적는다. 이 링크들이 지식 지도의 간선이 된다.

### 3. 출처 추적
모든 주제 문서의 `sources`에 원본 inbox 파일명을 기록한다(검증 가능성 유지). 핵심 사실 옆에는 가능하면 `(원본파일명)`을 병기한다.

### 4. 지식 지도(MAP.md) 갱신 ⭐
`brain/wiki/MAP.md`를 다시 정리한다 — **작게 유지**(요약+링크만):
- ① 통계(주제 수·총 단어 수 추정·갱신일)
- ② 주제 색인: 주제별 `[[slug]]` + 한 줄 요약 + 태그 (태그/카테고리별로 묶어도 좋다)
- ③ 연결 그래프: 주요 간선을 `A ↔ B — (관계)` 형태로 나열
- ④ 미해결 모순/확인필요 목록(있으면)

### 5. 처리 기록 남기기
`brain/.state/processed.json`에 이번에 처리한 파일들을 `{ "file": "...", "ingested_at": "YYYY-MM-DDTHH:MMZ", "topics": ["slug", ...] }` 형태로 추가한다. 기존 JSON 구조를 유지하며 append 한다.

### 6. 보고
무엇을 했는지 간결히 요약한다: 처리한 inbox 파일 수, 새로 만든 주제, 갱신한 주제, 새로 생긴 연결 수, 발견한 잠재 모순.

## 원칙
- inbox 원본은 **삭제하지 않는다**(처리 기록만 남긴다).
- 한국어로 작성한다. 추측은 `[확인필요]`로 표시한다.
- 한 번에 inbox가 매우 많으면, 가장 정보 밀도 높은 것부터 우선 처리하고 나머지는 다음 실행으로 미뤄도 된다(보고에 명시).
