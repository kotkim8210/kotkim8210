## 원본 V3 구조 (해독)
열: NO·상품명·옵션·수량·판매가(G)·배송비(H)·공급가(I)·원가위안(J)·수수료%(K)·물류비(L)·포장(M)·마케팅(N)·수수료(P)·부가세(Q)·1차합계(R)·소득세(S)·기타(T)·마진(U)·마진율(V)·공급처URL(X)·경쟁사URL(Z)
- 공급가 `=J*300` (환율 300 하드코딩 — 실환율 195에 운임·관세·통관을 얹은 **체감환율**)
- 마케팅 `=G*15%`, 기타 `=G*3%`, 수수료 `=(G*K)+(H*3.63%)`
- 부가세 `=((G+H)-(I+L+M+N+P))*10%` ← **마진의 10%** (근사)
- 소득세 `=R*16%` ← 법인 기준 고정
- 하단에 '월 목표금액 ÷ 30 ÷ 마진 = 일 판매수' 미니 계산기

## V4에서 고친 것
1. **소득세**: 고정 16% → **종합소득세 누진 + 지방소득세 10%** (연 과세표준 입력 → 세율표 INDEX/MATCH).
   - 개인 6.6%~49.5% vs 법인 9.9%/20.9% → **규모 커지면 개인이 불리**. V3의 16%는 개인 1,400만~5,000만 구간(16.5%)에 해당.
2. **부가세**: 마진×10% → **매출세액(판매가/11) − 매입세액**. 간이과세는 매출×1.5%.
   - **수입 매입세액**: 정식통관이면 공제, 구매대행·직송금이면 공제 0 (증빙 없음) → 스위치로 분기.
3. **환율·수수료·마케팅% 하드코딩 → '가정' 시트 1곳으로 분리** (200행 일괄 반영).
4. **적자에도 소득세가 음수로 계산되던 버그** → `MAX(0, 이익)`.
5. **소싱 판정 열 추가**(AA~AI): 경쟁사최저가·리뷰중앙·이길만한경쟁%·광고침투율·월검색량 → 손익분기가·가격여유·기회점수·GO/검토/SKIP. 조건부 서식으로 색상.
6. `fill_sourcing.py`: 쿠팡 크롤러 + 네이버 검색광고 API로 **연두칸 자동 채움** → "빈칸 채우면 소싱기" 요구 충족.

## 핵심 발견 (사용자에게 알릴 것)
- **K열 수수료 0.3(30%)이 마진을 죽이고 있다.** 8행 태양광 정원등 격자 8P 기준:
  - 수수료 30% → 마진 482원 (2.6%)
  - 수수료 10.8%(쿠팡 마켓플레이스 실제) → 마진 2,862원 (**15.4%**)

- V3 대비 V4 마진율은 소폭 보수적(3.0% → 2.6%) — 부가세를 정밀 계산해서.
