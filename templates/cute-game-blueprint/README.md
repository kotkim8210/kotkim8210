# 귀여운 캐주얼 게임 설계도 템플릿 (Cute Casual Game Blueprint)

Block Nova 프로젝트(PR #17)에서 **실제로 검증된 파이프라인**을 재사용 가능한 템플릿으로 만든 것입니다.
비개발자가 〔빈칸〕만 채우면, 클로드가 문서 작성부터 코딩·테스트·보고까지 끝까지 수행합니다.
(문서는 클로드, 코딩은 다른 도구 — 같은 분업이 필요 없다는 것이 Block Nova로 증명된 전제입니다.)

## 파일 구성

| 파일 | 역할 | 비유 |
|------|------|------|
| `CLAUDE.md` | 클로드에게 주는 **작업 지시서**. 규칙·단계·합격 기준 | 시공 계약서 + 검수 기준표 |
| `PRD.md` | 무엇을, 누구를 위해, 왜 만드는지 한 장 요약 | 사업 기획서 |
| `docs/game-design.md` | 게임 규칙·점수·후킹·리텐션 (GDD) | 게임 규칙서 |
| `docs/ui-spec.md` | 귀여움 스타일 가이드 + 디자인 토큰 + 금지 목록 | 인테리어 무드보드 |
| `docs/monetization.md` | 광고 SDK 이벤트·광고 지점 규칙 | 수익 설계도 |
| `docs/wireframes.html` | 브라우저로 열어보는 화면 설계도 (파스텔 예시) | 모델하우스 |

## 사용법 (3단계)

1. **복사** — 이 폴더를 통째로 복사해 새 게임 이름 폴더로 만듭니다. (예: `bubblepop/`)
2. **빈칸 채우기** — 각 문서의 `〔 〕` 표시를 채웁니다. 직접 채워도 되고, 아래 프롬프트로 클로드에게 인터뷰를 받아 채워도 됩니다:
   > "templates/cute-game-blueprint를 복사해서 새 게임 설계도를 만들 거야. 나에게 질문을 하나씩 던져서 〔빈칸〕을 함께 채워줘. 나는 비개발자야."
3. **발주** — 채워진 폴더가 저장소에 있는 상태에서 새 클로드 세션에 이렇게 말합니다:
   > "〔폴더명〕/CLAUDE.md를 읽고 Phase 1을 구현해줘. 나는 비개발자니까 실행 방법까지 포함해서 수용 기준 체크표로 보고해."

Phase 1 보고를 검수한 뒤 "Phase 2 진행해줘" 식으로 단계별로 진행하면 됩니다.

## 이 템플릿이 지키는 원칙 (Block Nova에서 배운 것)

- **수용 기준이 곧 신뢰 장치** — 코드를 못 읽어도, "이 테스트가 통과해야 커밋"이라는 체크표가 검수를 대신한다.
- **스택은 설계 단계에서 고정** — AI에게 선택지를 열어두면 세션마다 결과물이 흔들린다.
- **귀여움은 장식이 아니라 규칙** — 형태·색·피드백·감정 카피를 CLAUDE.md의 필수 규칙으로 못박는다.
- **플랫폼 심사 방어를 처음부터** — 로딩 3초·입력 3종·저사양 60fps는 나중에 고치기 가장 비싼 항목이다.
- **IP 안전** — 기존 인기 게임과 이름·아이콘·규칙이 혼동되면 안 된다(특히 낙하식 테트로미노는 상표·트레이드드레스 위험).
