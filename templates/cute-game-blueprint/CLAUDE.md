# CLAUDE.md — 〔게임 이름〕 빌드 지침 (v1.0)

〔한 줄 소개: 어떤 장르의 웹게임인지. 예: 8×8 매칭 퍼즐 웹게임 "Bubble Pop"〕 스펙 패키지.
발주자는 **비개발자** — 완료 보고는 실행 명령어까지 포함한다.
**목표: 〔출시 목표. 예: CrazyGames/Poki 공개 심사 통과 + 귀여운 비주얼로 타깃 유저 후킹〕.**

## 문서 우선순위
1. `docs/game-design.md`(규칙·후킹·리텐션) 2. `docs/ui-spec.md`(귀여움 토큰·주스)
3. `PRD.md` 4. `docs/monetization.md`(SDK·광고) 5. `docs/wireframes.html`(시각 참조)

## 스택 (고정 — 임의 변경 금지)
Vite + TypeScript + Tailwind, vanilla TS(프레임워크 금지), 백엔드·로그인 금지,
`localStorage`(`〔접두사. 예: bp:〕`)만, 게임 데이터는 `data/*.json` import 번들.
영어 UI 기본 + `?lang=ko`. `npm run build` → dist.

## 절대 규칙 A — 심사 방어 (전부 필수, Phase 4에서 자동 점검표 출력)
- **게임플레이 도달 ≤ 3초** (플랫폼 기준은 20초 — 마진 확보). 스플래시=로딩바 1개, 외부 요청 0, 상대경로만.
- **입력 3종**: 마우스 + 터치(드래그와 탭 모두) + **키보드**(화살표 커서, 숫자키 선택, Enter 실행, **P=일시정지**, M=음소거). ESC 단독 일시정지 금지.
- **기기별 분기**: 데스크톱에서 터치 전용 UI 숨김, "Tap"↔"Click" 문구 자동 전환, 데스크톱은 중앙 세로 컬럼 + 측면 앰비언트 배경.
- **저사양 보장**: 4GB 크롬북 기준 60fps — transform/opacity만, 파티클 ≤24, 프레임타임 샘플링으로 자동 이펙트 축소.
- body에 `user-select:none` 계열(롱프레스 확대 방지), iframe 내 정상 동작(전체화면 API 직접 호출 금지).
- 오디오: WebAudio 합성음만(외부 파일 0), 레벨 일정, 백그라운드 탭에서 정지·복귀 시 재개.
- **IP 안전**: 게임명·아이콘·핵심 규칙이 기존 인기 게임과 혼동 금지. 로고 자체 제작.

## 절대 규칙 B — 귀여움 (타깃: 아기자기·깜찍 중시 유저. ui-spec이 상세 정의)
- **형태 언어**: 모든 모서리 둥글게(토큰으로 통일), 날카로운 각·차가운 금속 질감 금지.
- **색**: 〔팔레트 방향. 예: 파스텔 + 크림 배경〕. 단, 조각끼리 **대비로 구분** 가능해야 하고
  **색+무늬 이중 코딩**(색약 대응 마이크로 글리프 — 하트·발도장·눈 같은 귀여운 무늬 겸용) 필수.
- **피드백은 감정으로**: 배치=스쿼시&팝, 클리어=파티클+상승음, 콤보=칭찬 문구 사다리(피치업 사운드 동기화),
  신기록=콘페티+팡파르, 실패 화면=응원 카피("Best까지 −N · 한 판이면 넘어요!").
- **빈 화면 금지**: 게임오버·일시정지·로딩에도 표정/메시지/마이크로 애니메이션으로 감정 공백을 채운다.
- **마스코트**: 〔마스코트 콘셉트. 예: 게임 화면 구석의 슬라임이 콤보에 반응해 표정 변화〕.
- **금지**: 텍스트 과밀, 원색 과다, 복잡한 모달 남발, 44px 미만 터치 타깃, 색만으로 정보 구분.
- 모든 모션은 `prefers-reduced-motion` 대체 경로 필수.

## 광고 어댑터 (`src/ads/adapter.ts`)
인터페이스: `init() / loadingStart() / loadingStop() / gameplayStart() / gameplayStop() /
happytime() / showInterstitial() / showRewarded(cb)`.
`VITE_ADS=off|〔포털명〕` 분기 — off는 콘솔+즉시 콜백, 포털 모드는 SDK 삽입 지점 주석만(활성화는 발주자).
**happytime = 〔최고 순간 3곳. 예: 대형 콤보 폭발·퍼펙트 클리어·신기록〕에서만** 호출.

## 구현 단계 (단계별 수용 기준 통과 후 커밋 — 발주자가 코드 대신 이 체크표로 검수한다)

### Phase 1 — 코어 + 크로스 입력
- [ ] vitest: 핵심 판정 3케이스(〔게임 규칙의 핵심 판정 3가지. game-design §판정에 정의〕), 게임오버 판정, 〔스폰/생성 규칙 테스트. 예: 가중치·직전 조합 금지〕
- [ ] 마우스/터치/키보드 3입력 모두 조작 가능, 미리보기(고스트)·불가 표시
- [ ] 점수·콤보·〔시그니처 게이지〕, 베스트 저장, 380px 무스크롤 + 데스크톱 레이아웃

### Phase 2 — 후킹 + 귀여움 주스
- [ ] **첫 실행 골든 퍼스트 무브**: 프리셋 상황 → 첫 조작 1~2수에 큰 성공 체험 + 〔선충전 보상〕, 코치마크 ≤3개(비주얼·스킵 가능·게임플레이 내)
- [ ] 주스 팩(ui-spec §주스): 스쿼시&팝, 파티클, 점수 카운트업, 콤보 칭찬 사다리+피치업, 햅틱, 신기록 콘페티
- [ ] 〔시그니처 연출. 예: 폭발 연출〕 + happytime 호출, reduced-motion 대체

### Phase 3 — 리텐션 메타
- [ ] 스트릭 + 실드(7일마다 1개·결손일 자동 소모), 레벨/XP/랭크(L1 30% 선충전)
- [ ] 주간 퀘스트 3종(ISO 주 시드 결정적) + 진행 바(마지막 10% 글로우)
- [ ] 게임오버 근접실패 화면: "Best까지 −N" + 다음 요소 공개 + 15% 이내 특수 응원 카피
- [ ] 〔수집 요소. 예: 마스코트 도감 — 플레이 누적으로 한 칸씩 공개〕
- [ ] vitest: XP 임계 함수, 주간 퀘스트 시드 결정성, 첫 실행 프리셋 성립

### Phase 4 — 포털 하드닝
- [ ] `VITE_ADS=〔포털명〕` 빌드, 인터스티셜(게임오버 2회당·결과 화면 후만)·리워드(부활/재도전) 연결
- [ ] 절대 규칙 A·B 전 항목 자체 점검 → **점검표를 표로 출력**(항목·상태·근거 파일)
- [ ] 포털 빌드 zip + 번들 크기 보고(목표 ≤ 2MB)
- [ ] Chrome/Edge/Safari + 모바일 뷰포트 스모크 결과 표

## 완료 보고 형식
실행법(비개발자용 명령어) + 수용 기준 체크표(증거 포함) + (P4는) 심사 방어 점검표 + 남은 리스크 3줄.
