# 수익화·유통 — Block Nova

## 0. 원칙 (정직)
"확실한 수익"은 없다. 보장되는 건 **비용 ≈ 0**(포털이 호스팅·트래픽·광고를 전부 제공)이며,
수익 크기는 노출·리텐션에 달렸다 — 전부 첫 달 포털 대시보드로 실측한다.

## 1. 유통 경로 (포털 우선 — 도메인·호스팅 불필요)
| 순서 | 채널 | 조건 |
|---|---|---|
| 1 | **CrazyGames** (developer.crazygames.com) | 파일 CDN 무료 호스팅, 광고 수익 배분, €100부터 월 지급(PayPal/송금). **2개월 한정 독점 선택 시 배분 +50%** |
| 2 | **Playgama Bridge** | 독점 기간 후 멀티포털 일괄 배포(개발자 몫 최대 80%) |
| 3 | Poki | 큐레이션 엄격 — 1~2호 지표 확보 후 도전 |
| 후순위 | 자체 사이트 + AdSense | 트래픽 자가 조달 필요 → 포털 검증 후에만 |

## 2. 광고 설계 (게임 내 훅 — adapter 경유)
| 자리 | 형식 | 규칙 |
|---|---|---|
| 게임오버 결과 화면 | 인터스티셜 | **2회 오버당 1회**, 플레이 중 삽입 금지(리텐션 보호) |
| 부활 | 리워드 | 판당 1회, 랜덤 12셀 제거 후 계속 |
| 데일리 재도전 | 리워드 | 일 1회, 기록은 첫 판만 인정 |
리워드는 캐주얼 광고수익의 최상 포맷(업계 45% 비중) — 옵트인률을 KPI로 측정.

## 3. §SDK — CrazyGames 활성화 절차 (발주자용, 승인 후)
1) 개발자 포털 가입 → 게임 등록 → `dist` zip 업로드(빌드 스크립트가 생성)
2) 문서의 HTML5 SDK 스니펫을 `src/ads/adapter.ts` 주석 지점에 붙여넣기 — 어댑터가 이미
   `loadingStart/Stop · gameplayStart/Stop · happytime · interstitial · rewarded` 호출 지점을 갖고 있어 연결만 하면 됨
3) 포털 프리뷰에서 로딩 이벤트·광고 동작 확인 → 제출
4) **Basic Launch 동안 광고는 포털 정책상 비활성**(순수 지표 측정 목적) — 수익은 Full Launch부터.
   승격 판정 지표 = 평균 플레이타임·게임플레이 전환율·리텐션 → §후킹/리텐션 설계가 곧 승격 전략

## 4. 수익 시나리오 (⚠전부 가설 — 공개 데이터 희박, 실측으로 교체)
| 시나리오 | 상태 | 기대 |
|---|---|---|
| 심사 탈락 | 가능성 실존 | 2호(마작 짝맞추기)로 즉시 전환, 피드백 반영 재제출 |
| Basic Launch 통과 | 기본 | 월 수만~수십만 원대에서 시작하는 사례가 일반적 |
| Full Launch·추천 노출 | 상방 | 월 수백만 원대 — 소수 상위 게임의 영역 |
비용이 0이므로 어느 시나리오에도 적자 없음. **포트폴리오(1호 블록 → 2호 마작)가 전략의 본체.**

## 5. 콘텐츠·법 체크
자체 제작 도형·색·연출만 사용(타사 IP·에셋 0), 개인정보 미수집(localStorage만) 고지 1페이지,
사운드는 합성음(저작권 이슈 0), 게임명 상표 충돌 간단 검색 후 확정.
