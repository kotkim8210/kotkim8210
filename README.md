# 🧠 제2의 뇌 (Second Brain) — 스스로 진화하는 클로드 위키

> 분류하지 말고 그냥 던져라. **연결·요약·정제·검색은 클로드가 한다.**

방대한 정보를 수동으로 분류하느라 시간을 낭비하지 않고, 그냥 `brain/inbox/`에 던져넣기만 하면
클로드(Claude)가 스스로 **요약된 지식 지도**를 만들고, 정보 사이의 **연결고리**를 찾아내며,
밤마다 **드림 시퀀스(Dream Sequence)** 로 모순과 중복을 정제하는 자가 진화형 지식 창고입니다.

## ✅ 어디서나 작동 — GitHub도, API 키도 필요 없음

이 시스템의 두뇌는 **GitHub가 아니라 [`CLAUDE.md`](CLAUDE.md) + 슬래시 명령**입니다.
따라서 **어떤 클로드 세션에서든**(웹 · 데스크톱 앱 · IDE · CLI) 이 저장소를 열기만 하면 그대로 작동합니다.

| | 세션에서 직접 (기본 · 추가 비용 0) | GitHub Action (선택 · 완전 자동) |
|---|---|---|
| 수집 | `/ingest` | inbox push 시 자동 |
| 정제 | `/dream` | 주 1회 야간 자동 |
| 검색 | `/recall <질문>` | — |
| 필요한 것 | **없음** — 클로드 세션만 있으면 됨 | `ANTHROPIC_API_KEY` 시크릿 (1회 설정) |

> 즉, API 키나 GitHub 설정을 **전혀 하지 않아도** 모든 기능이 동작합니다.
> GitHub Action은 "내가 아무것도 안 해도 알아서 돌아가는" 편의를 원할 때만 켜는 **선택 사항**이며,
> 키가 없으면 워크플로는 **비용 없이 조용히 건너뜁니다.**

## 🚀 3단계 사용법

### 1단계 — 무가공 데이터 축적 (Data Dumping)
연구 자료, 웹 스크랩, 메모, PDF 발췌, 회의록… **무엇이든** `brain/inbox/`에 그대로 넣습니다.
폴더를 나누거나 이름을 고민할 필요가 전혀 없습니다.

```bash
# 예: 아무 메모나 던져넣기
echo "오늘 읽은 논문 요약 ..." > brain/inbox/$(date +%F)-아무거나.md
```

### 2단계 — 자가 진화형 위키 구축
클로드 세션에서 한 줄만 실행하면, inbox의 모든 지식을 스캔해 주제별 문서로 정리하고,
서로의 연결고리를 `[[위키링크]]`로 이어 **지식 지도(`brain/wiki/MAP.md`)** 를 만듭니다.

```text
/ingest
```

### 3단계 — 원하는 답을 몇 초 만에
질문하면 클로드는 먼저 작은 **MAP 인덱스**만 읽어 위치를 찾고, 관련 문서 1~3개만 펼쳐 답합니다.
그래서 데이터가 40만 단어를 넘어도 검색이 느려지지 않습니다.

```text
/recall 작년에 정리한 마케팅 전략의 핵심이 뭐였지?
```

## 🌙 드림 시퀀스 (Dream Sequence) — 이 시스템의 심장

> **클로드가 스스로 지식을 검토하고 정제합니다.** 다음을 수행하고 변경 사항을 기록·커밋합니다:

1. **모순 탐지** — 서로 충돌하는 주장을 찾아 신뢰도·최신성 기준으로 정리
2. **중복 병합** — 겹치는 주제를 하나의 정본(canonical)으로 통합
3. **구식 정리** — 더 이상 유효하지 않은 지식을 `brain/archive/`로 이동(삭제 아님)
4. **통찰 합성** — 여러 주제를 가로지르는 **새로운 연결**을 발견해 `brain/insights/INSIGHTS.md`에 누적
5. **재색인** — `[[위키링크]]`와 `MAP.md`를 다시 정리하고, 모든 변경을 `.state/dream-log.md`에 기록

이 과정이 반복되며 **낡은 지식은 걸러지고 새로운 통찰이 쌓여**, 시스템의 정확도와 성능이 시간이 갈수록 극대화됩니다.

### ▶ 실행 방법 — 두 가지 길

**길 1 (기본 · 추가 비용 0 · 권장):** 아무 클로드 세션에서나 직접 실행
```text
/dream
```
설정도, API 키도, GitHub도 필요 없습니다. 생각날 때(또는 자료를 한참 넣은 뒤) 한 번 돌리면 됩니다.

**길 2 (선택 · 완전 자동):** 잠든 사이에도 알아서 돌게 하고 싶다면
1. [Anthropic Console](https://console.anthropic.com/)에서 API 키 발급
2. 저장소 → **Settings → Secrets and variables → Actions → New repository secret**
3. 이름 `ANTHROPIC_API_KEY`, 값에 API 키 붙여넣기 → 끝
4. **매주 일요일 새벽**(KST) 자동 정제됩니다. 비용을 아끼려 빈도를 주 1회로 잡았고, `.github/workflows/dream-sequence.yml`의 `cron`만 바꾸면 조정됩니다. **Actions 탭 → Run workflow**로 즉시 실행도 가능.

> 키를 설정하지 않으면 자동화는 **비용 없이 그냥 건너뜁니다.** 손해는 전혀 없습니다.

# 검증 우선 창업 툴킷 (Validation-First Startup Toolkit)

> **핵심 철학 한 줄:** "좋아요·조회수"가 아니라 **"지불 신호(Commitment Signal)"**로 검증한다.
> 아이디어 → **개발 전에 시장 검증** → 지불 신호가 터진 것만 실제 개발에 자원 투입.

1인 창업자가 *개발에 시간을 쏟기 전에* 수요를 검증하기 위한 도구 모음입니다.
빌드·설치 불필요 — 순수 HTML/CSS/JS. 파일을 더블클릭해 브라우저로 열거나, 정적 호스팅에 그대로 올리면 됩니다.

## 왜 이 순서인가 (Stage-Gate)

대부분의 1인 창업이 죽는 지점은 "만들기"가 아니라 **"안 팔리는 걸 만들기"**입니다.
그래서 각 단계마다 **통과(GO)/탈락(KILL) 기준**을 두고, 통과한 것만 다음 단계로 넘깁니다.

| 단계 | 활동 | 통과(GO) | 탈락(KILL) | 사용 도구 |
|---|---|---|---|---|
| 0. 문제 선별 | 페인 후보 10개 점수화 | 상위 2~3개 압축 | "이미 잘 풀린 문제" 제거 | **Tool 01** |
| 1. 수요 검증 | 랜딩+가짜버튼, 개발 0줄 | CTA 클릭률 ≥ 합격선 + 등록 N건 | 합격선 미달 → 즉시 폐기 | **Tool 02 → 03** |
| 2. 선판매 검증 | 베타 유료 슬롯/사전결제 | 실제 결제자 ≥ X명 | 무료엔 몰려도 결제 0 | **Tool 03** |
| 3. 최소 제품 | 결제 고객용 핵심기능만 AI로 빌드 | 재방문/리텐션 유지 | 리텐션 붕괴 | **Tool 03** |
| 4. 운영·확장 | 반복작업만 자동화, 판단은 사람 | LTV:CAC ≥ 3 | 단위경제 역전 | **Tool 03** |

## 도구 구성

### 🏠 `index.html` — 허브
세 도구로 연결되는 시작 페이지 + 전체 흐름 요약.

### 📊 Tool 01 — `pain-scorer.html` · 페인포인트 점수화 시트
레딧·커뮤니티에서 모은 고객 불편을 네 축으로 점수화(1~5)해 우선순위를 매깁니다.

- **빈도 × 강도 × 지불가능성 × 경쟁공백** (가중치 조절 가능, 기본은 지불가능성·경쟁공백에 가중)
- 점수 ≥ 3.8 → `GO`, 3.0~3.8 → `WATCH`, < 3.0 → `KILL`
- **지불 의향 증거(인용·링크)** 칸이 비면 −0.3 페널티 → 추측 방지
- CSV 내보내기, localStorage 자동 저장
- ⚠️ 주의: *레딧에서 불평하는 사람 ≠ 돈 내는 사람.* 그래서 "지불가능성" 축과 "증거" 칸이 핵심입니다.

### 🚪 Tool 02 — `validation-landing.html` · 검증용 랜딩 + 가짜 결제버튼
**개발 0줄**로 수요를 테스트하는 스모크 테스트(가짜 문) 페이지.

- 모든 문구를 **클릭해서 바로 수정**(contenteditable, localStorage 저장)
- 가격 3종 선택 + **사전 예약 버튼** → 이메일 캡처 모달. "유료 결제 의향" 체크는 *말로 한 약속(약한 신호)*, 등록 후 뜨는 **예약금 결제(2단계)가 진짜 강한 신호(돈)**
- **퍼널 자동 추적**: 방문 → 50% 스크롤 → CTA 클릭 → 이메일 등록 → 유료 의향(약) → **예약금 결제 클릭(강)**
- 우측 하단 **📊 실시간 미니 대시보드**(CTR/전환율/퍼널 막대/리드 목록/CSV)
- 외부 연동(선택): 파일 상단 `CONFIG` — `submitEndpoint`(Formspree/Tally/Google Form)로 등록 데이터 전송, `paymentLink`(Stripe/Gumroad/Lemon Squeezy)로 **2단계 실제 결제** 연결. `window.gtag`(GA4)·`window.fbq`(Meta Pixel)가 있으면 이벤트 자동 전송.

> **정직한 신호 위계:** 좋아요·조회(관심) < 이메일 등록·"의향" 체크(*말*, 약함) < **예약금·사전결제(*돈*, 강함)**. 1단계 랜딩은 "관심"까지만 검증합니다 — **유료 니즈는 `paymentLink`로 실제 돈을 받는 2단계에서만 확인됩니다.** 스모크 테스트의 GO를 "수요 증명"으로 착각하지 마세요.

### 🧮 Tool 03 — `gate-calculator.html` · 단계별 합격선 계산기
측정값을 넣으면 단계마다 `GO`/`WATCH`/`KILL`을 판정.

- **합격선 잠금**: 테스트 *전에* 기준을 숫자로 박고 잠가서 사후 합리화 차단
- 1단계: CTA 클릭률·등록 전환율 + **표본 충분성 경고**(기본 100명 미만이면 신뢰 금지)
- 2단계: 실제 결제자 수, 등록→결제 전환율
- 3단계: 30일 리텐션 / 이탈률
- 4단계: **LTV·CAC·LTV:CAC 비율·CAC 회수기간** (3:1 룰)
- 종합 판정 + 다음 행동 제안

---

## 추천 사용 흐름

1. **Tool 01**에서 레딧 페인 10개를 점수화 → `GO` 상위 2~3개 선정
2. 선정된 문제마다 **Tool 02**로 랜딩을 만들어(문구만 교체) SNS·커뮤니티에 뿌림
3. **Tool 03**에서 *테스트 시작 전에* 합격선을 잠그고, 매일 수치를 입력해 `GO/KILL` 판정
4. 1단계를 통과한 것만 **선판매(실제 결제)**로 → 또 통과한 것만 **실제 개발** 시작

> 여러 개를 동시에 싸게 던지고, **지불 신호가 터진 1~2개에만 개발 자원을 몰빵**하는 게 이 방식의 진짜 강점입니다.

## 흔한 함정 (체크리스트)

- [ ] "반응"을 좋아요로 정의하지 않았는가? → **지불 신호(등록·클릭·사전결제)**로만 판정

- [ ] 레딧 페인의 "지불 의향 증거"를 실제로 남겼는가?

- [ ] 자동화는 *반복작업*에만, 유통·메시지·가격 *판단*은 사람이 하는가?

## 데이터 & 프라이버시

모든 입력은 기본적으로 **브라우저 localStorage**에만 저장되며 서버로 전송되지 않습니다.
Tool 02의 `CONFIG.submitEndpoint`를 직접 설정한 경우에만 외부로 등록 데이터가 전송됩니다.
