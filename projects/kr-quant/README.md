# KR-Quant — 한국 주식 중장기 자동분석 시스템 (설계안 v0.1)

> **한 줄 정의:** "추천 종목 리스트"가 아니라 **재현 가능한 투자 시스템**을 만든다.
> 공시·재무(본질가치) × 수급 × 주봉/월봉 추세 × 커뮤니티 역발상 × **정책·공시 시나리오** 를
> 하나의 워크플로로 결합하고, 그 결과를 **사람이 읽는 리포트**와 **기계가 읽는 JSON** 둘 다로 출력한다.

## 두 개의 트랙

| | **가치·수급 트랙** | **시나리오 트랙** (§10~11) |
|---|---|---|
| 출발점 | 종목의 재무·수급 상태 | 외부 촉매(정책·법령·예산·대형 공시) |
| 핵심 질문 | 사업이 좋아지고 있는가 | 촉매가 **미래 재무제표를 바꾸는가** |
| 매수 시점 | 4중 게이트 동시 충족 시 | 촉매 발생 시가 아니라 **검증 확인 후** |
| 게이트 | 4중 동시충족 | 4중 동시충족 **+ 확인 4항목 중 3개** (완화 아님, 추가) |

시나리오 트랙은 우회로가 아니다. **일반 게이트를 전부 통과한 뒤 조건을 더 만족해야 한다.**
"정책주니까 재무는 봐준다"는 경로는 설계상 존재하지 않는다.

## 설계를 관통하는 6개 원칙

1. **PIT(Point-In-Time) 절대 준수** — 재무 데이터는 *공시 접수일(rcept_dt) 이후*에만 사용 가능.
   한국 시장 백테스트 실패의 1순위 원인이 여기다. 12월 결산법인의 사업보고서는 익년 3월 말에야 존재한다.
2. **4중 동시충족 게이트** — 재무 / 공시 / (수급·기술) / 역발상이 **동시에** 맞아야 매수 후보가 된다.
   한 축만 좋은 종목은 구조적으로 통과할 수 없다.
3. **커뮤니티·기대는 구조적으로 보조신호** — 정성+역발상 가중치 합을 20/100으로 **상한**하고,
   시나리오 축 안에서도 *기대성(정책적합 22점)보다 검증성(실적반영 30점)에 더 큰 배점*을 준다.
   여론이나 테마만으로는 매수 임계(70점)를 넘길 수 없다. 규율을 의지가 아니라 수식에 넣는다.
4. **이벤트는 호재/악재가 아니라 컨텍스트** — 액면분할·무상증자 등은 그 자체로 부호를 갖지 않고,
   *직전 상승률 · 밸류에이션 백분위 · 감성 위치*의 조합으로 해석된다(삼성전자 2018형 vs 카카오 2021형).
5. **촉매가 생겨도 즉시 사지 않는다** — 시나리오 포지션은 `WATCH` → `CONFIRM_PENDING` → `SCALE_IN`
   상태머신을 거치며, 앞의 두 상태에서는 **매수가 물리적으로 차단**된다. 여기에 5조건 **과열 거부권**이
   더해져, 3개 이상 충족 시 TOTAL이 95점이어도 신규 매수를 막는다.
6. **확률적 서술** — 모든 결론에 신뢰도 점수, 전제조건, 무효화 조건(invalidation)을 함께 낸다.
   "무조건 오른다"류 표현은 리포트 생성기에서 금칙어로 **차단(치환 아님)** 한다.

## 빠른 시작 (구현 완료 후 기준)

```bash
cp .env.example .env          # DART_API_KEY, NAVER_CLIENT_ID/SECRET 입력
make setup                    # 의존성 설치
make bootstrap                # 종목마스터 + 10년 시세/재무 초기 적재

krq screen     --date 2026-08-05 --top 30      # 전체 유니버스 스캔 → 후보 랭킹
krq deepdive   005930 --out reports/           # 단일 종목 A~F 리포트(MD+JSON)
krq scenario   list                            # 활성 시나리오 보드(상태별 종목 현황)
krq backtest   --from 2015-01-01 --to 2025-12-31 --walk-forward
krq eventstudy --event-type "단일판매공급계약" --windows 5,21,63,126
krq watchlist  --sync                          # 보유/관심 종목 매도 경고 점검
```

Claude Code 슬래시 명령: `/screen` · `/deepdive` · `/scenario` · `/backtest` · `/watchlist`
(정의는 `docs/05-project-structure.md` 참조)

## 현재 상태

**설계 단계 완료 / 구현 미착수.** 이 묶음은 코드를 생성하기 위한 사양서이며, 아직 실행 가능한 코드는 없다.
문서 내 수치(가중치·임계값·기대 보유기간 등)는 **검증 전 초기값**이다. 모든 값은 `config/*.yaml`에 외부화되어 있고,
`docs/04-backtest.md`의 검증 프로토콜을 통과해야만 확정값으로 승격한다.
검증되지 않은 항목은 문서 내에서 `[검증필요]` 마커로 표시했다.

## 면책

이 시스템은 **리서치·의사결정 보조 도구**이며 투자 자문이 아니다. 산출되는 모든 신호는 확률적 추정이고,
과거 패턴이 미래에 반복된다는 보장은 없다. 최종 투자 판단과 그 결과에 대한 책임은 사용자 본인에게 있다.
